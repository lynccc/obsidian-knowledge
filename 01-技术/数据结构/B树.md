# B-树

## 核心概念

B-树是一种**多路平衡搜索树**，是 [[二叉搜索树BST]] 的推广。每个节点可以有 m 个孩子（m 阶 B-树），从而大幅**降低树高**，减少磁盘 I/O 次数。B-树是数据库索引和文件系统的核心数据结构。

### m 阶 B-树的定义

一棵 m 阶 B-树满足：
1. 每个内部节点最多有 **m 棵子树**，即最多 m-1 个关键码
2. 每个内部节点（除根）至少有 **⌈m/2⌉ 棵子树**，即至少 ⌈m/2⌉-1 个关键码
3. 根节点至少有 **2 棵子树**（除非树只有根）
4. 所有**叶节点**（外部节点）在同一层，不包含关键码，仅作为查找失败的标志
5. 关键码在节点内**有序排列**，子树指针交错其间

## 关键要点

### 查找

从根开始，在当前节点内**顺序或二分查找**关键码；找到则返回，否则沿对应子树指针下降。每次 I/O 读入一个完整节点（一页/一块）。

查找路径长度 = 树高 h = O(logₘ n)，由于 m 通常很大（如 100~1000），树高极低（通常 2~4 层）。

### 插入与上溢分裂

1. **查找定位**：沿搜索路径找到应插入的叶节点位置
2. **插入关键码**：插入到对应节点的有序位置
3. **上溢处理**：若节点关键码数超过 m-1，则**分裂**：
   - 取中间关键码**上提**至父节点
   - 左右两半分别成为父节点的两个子节点
   - 若父节点也溢出，递归分裂（最坏情况增加一层树高）

```
    [k1 | k2 | k3 | k4]  ← 5 阶 B-树，4 个关键码溢出
              ↓ 分裂
      [k2]
      /    \
   [k1]   [k3 | k4]
```

### 删除与下溢合并

1. **查找定位**：找到待删除关键码所在节点
2. **若在内部节点**：用**中序后继**（或前驱）替换，转为删除叶节点中的关键码
3. **下溢处理**：若删除后节点关键码数少于 ⌈m/2⌉-1：
   - **借位**：从兄弟节点借一个关键码（通过父节点中转）
   - **合并**：若兄弟也刚好够用，则与父节点中的关键码合并，父节点可能继续递归下溢

### 性能

| 操作 | 时间复杂度 | 磁盘 I/O |
|------|-----------|----------|
| 查找 | O(logₘ n) | O(h) 次 |
| 插入 | O(logₘ n) | O(h) 次，最多 1 次分裂 |
| 删除 | O(logₘ n) | O(h) 次，最多 1 次合并 |

> [!tip] 磁盘友好
> B-树的节点大小通常设计为恰好等于磁盘页大小（如 4KB），使得每次 I/O 读取一个完整节点，最大化 I/O 效率。

## 与其他概念的联系

- B-树是 [[平衡二叉搜索树]] 的多路推广
- **B+ 树**是 B-树的变体，关键码只存于叶节点，叶节点间用链表相连，更适合范围查询
- 与 [[红黑树]] 对比：红黑树适合**内存**中的有序查找；B-树适合**磁盘/外存**中的大规模数据索引
- 2-3 树、2-3-4 树分别是 3 阶、4 阶 B-树的特例
