# 散列表 HashTable

## 核心概念

散列表通过**散列函数**将关键码直接映射到数组下标，实现期望 O(1) 的查找/插入/删除。是词典ADT最高效的实现方式。

## 关键要点

### 散列函数
将关键码空间映射到地址空间的函数，理想情况下均匀分布、计算高效。
- **除余法**：`h(key) = key % M`，M 取素数效果更好
- **MAD法**：`(a*key + b) % M`，消除除余法的周期性
- **散列码转换**：对字符串等非整型关键码，先转换为整数再散列（如多项式散列码）

### 冲突（Collision）
不同关键码映射到同一地址。冲突不可避免，关键在于排解策略。

### 装填因子 λ
λ = n / N（元素数 / 桶数）。λ 越大，冲突越多，性能下降。

### 冲突排解

#### 开散列（拉链法）
每个桶维护一个链表，冲突元素挂入同一桶的链表。

#### 闭散列（开地址法）
冲突元素存放在表内其他空桶。探测策略：
- **线性试探**：逐桶线性探测 `h(key)+1, h(key)+2, ...`
  - 优点：缓存友好
  - 缺点：主聚集（primary clustering）
- **平方试探**：`h(key)+1², h(key)+2², h(key)+3², ...`
  - 减少主聚集，但可能有二级聚集
- **双向平方试探**：正负交替 `+1², -1², +2², -2², ...`
  - 当表长为 4k+3 的素数时，保证探测序列遍历全表

### 查找与删除
- 查找沿探测序列逐桶比较，直到找到或遇空桶
- 闭散列中删除需用**懒删除**标记（不能直接置空，否则破坏探测链）

### 完美散列
在已知全部关键码的情况下，可构造无冲突的散列函数，实现 O1 最坏情况查找。

### 复杂度
| 操作 | 期望时间 | 最坏时间 | 条件 |
|------|---------|---------|------|
| 查找 | O(1) | O(n) | λ 较小时 |
| 插入 | O(1) | O(n) | 同上 |
| 删除 | O(1) | O(n) | 同上 |

## 与其他概念的联系
- 与[[跳转表Skiplist]]：散列表不保持有序性，跳转表支持顺序遍历
- 与[[二叉搜索树BST]]：散列表期望 O(1) vs BST O(log n)，但 BST 支持范围查询
- 与[[桶排序与基数排序]]：桶排序直接利用散列思想分配元素
