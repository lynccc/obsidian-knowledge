# 栈与递归

## 核心概念

**递归函数的执行本质上就是栈操作**。每次函数调用会在调用栈上创建一个新的栈帧（stack frame），保存局部变量、参数和返回地址；函数返回时弹出栈帧。

## 函数调用栈的工作机制

```
调用 f(3)
├─ push: f(3) 的栈帧（参数、局部变量、返回地址）
│  ├─ push: f(2) 的栈帧
│  │  ├─ push: f(1) 的栈帧
│  │  │  └─ 返回 → pop f(1)
│  │  └─ 返回 → pop f(2)
│  └─ 返回 → pop f(3)
```

1. **调用**：将新栈帧压入调用栈（类比 `push`）
2. **返回**：弹出当前栈帧，恢复调用者的上下文（类比 `pop`）
3. **栈溢出**：递归过深导致调用栈空间耗尽（stack overflow）

## 关键要点

1. **递归 = 隐式栈**：任何递归算法都可以改写为显式使用栈的迭代版本
2. **尾递归**：递归调用是函数最后一步操作时，编译器可优化为跳转，避免栈增长。见 [[尾递归消除]]
3. **递归的代价**：
   - 每层调用消耗 O(1) 栈空间（局部变量、返回地址等）
   - 总空间复杂度 O(递归深度)
   - 函数调用有开销（压栈/出栈/跳转）
4. **何时用递归**：代码清晰性优先时；问题天然具有递归结构时（如树遍历、分治）
5. **何时避免递归**：递归深度大、性能敏感时，改用显式栈的迭代版本

## 示例：斐波那契的递归与栈视角

    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);
}
