# 并查集

## 🗣️ 通俗讲解

> 并查集就像管理"分组"——一开始每个人自成一组，然后不断地把两个组合并成一个组。支持两种操作：合并两个组，查询某个人属于哪个组。用了路径压缩和按秩合并后，每次操作几乎 O(1)。
>
> 大白话：找组长的时候，顺便把路上遇到的人都直接挂到组长下面，下次找就快了。

## 📖 核心概念

**并查集**（Union-Find）是一种管理"分组"的数据结构，支持合并集合和查询元素所属集合。

### 三种操作

| 操作 | 说明 |
|------|------|
| `MAKE-SET(x)` | 创建只包含 x 的新集合 |
| `UNION(x, y)` | 合并包含 x 和 y 的集合 |
| `FIND-SET(x)` | 返回 x 所在集合的代表 |

### 应用：连通分量

```python
def connected_components(G):
    for v in G.vertices:
        make_set(v)
    for u, v in G.edges:
        if find_set(u) != find_set(v):
            union(u, v)
```

### 不相交集合森林

用**有根树**表示每个集合：
- 每个节点只指向父节点
- **根节点**就是代表元素
- 每个节点有 `rank`（秩，高度上界）

```python
def make_set(x):
    x.parent = x
    x.rank = 0

def find_set(x):
    if x != x.parent:
        x.parent = find_set(x.parent)  # 路径压缩
    return x.parent

def union(x, y):
    link(find_set(x), find_set(y))

def link(x, y):
    if x.rank > y.rank:
        y.parent = x
    else:
        x.parent = y
        if x.rank == y.rank:
            y.rank += 1
```

### 按秩合并（Union by Rank）

每次合并时，让 rank 小的根指向 rank 大的根。这样树的高度增长很慢。

### 路径压缩（Path Compression）

在 `FIND-SET` 的过程中，把查找路径上的所有节点直接指向根。第一次可能要走很长的路径，之后路径上的所有节点都直接指向根。

### 两种启发式联合使用

**定理**：按秩合并 + 路径压缩，m 次操作的时间为 **O(m · α(n))**

其中 α(n) 是 Ackermann 函数的反函数，增长极其缓慢。对于任何实际可能出现的数据规模，α(n) ≤ 4。所以实际上每次操作就是 **O(1)**！

### 各种方案对比

| 方案 | m 次操作时间 |
|------|-------------|
| 链表 + 简单合并 | O(m + n²) |
| 链表 + 加权合并 | O(m + n log n) |
| 森林 + 按秩合并 | O(m log n) |
| 森林 + 路径压缩 | O(m log n)（最坏） |
| 森林 + 按秩合并 + 路径压缩 | O(m · α(n)) ≈ O(m) |

## 关键要点

1. 并查集是管理"分组"的高效数据结构
2. **按秩合并**：矮树挂到高树下面，总高度不增加
3. **路径压缩**：找组长的时候，顺便把路上遇到的人都直接挂到组长下面
4. 两种启发式联合使用后，每次操作近乎 O(1)
5. 并查集是 Kruskal 算法的核心数据结构
