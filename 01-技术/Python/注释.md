# 💬 Python 注释

## 核心概念

注释 = **给代码写的"便签"**，Python 会自动忽略它

类比：**注释就像课本上的铅笔笔记** —— 你在课本空白处写的笔记不会影响课本正文，但能帮助你（和别人）理解内容。

```python
# 这是一条注释，Python 会忽略它
print("Hello Python people!")   # 这也是注释，写在代码后面也可以

# 输出：
# Hello Python people!
# （注释不会出现在输出中）
```

---

## 一、如何写注释

注释用 `#` 开头。`#` 后面的所有内容都是注释。

```python
# 这是单行注释，# 后面的字 Python 都会忽略
print("Hello")    # 这也是注释，写在代码后面

# 输出：
# Hello
```

**⚠️ 注意：** `#` 必须写在一行的开头，或者代码的后面。不能把 `#` 写在字符串里面：

```python
# ✅ 正确：# 在代码前面
# 打印问候语
print("Hello")

# ✅ 正确：# 在代码后面
print("Hello")    # 打印问候语

# ❌ 错误：# 在字符串里面，会被当成普通文字
print("Hello # world")   # 输出：Hello # world（注释号被当成文字了）
```

---

## 二、什么时候写注释

### ✅ 好的注释：解释"为什么"

```python
# 好的注释：解释为什么这样做
# 使用小写存储，因为用户输入的大小写可能不一致
favorite_language = 'Python'.lower()
print(favorite_language)

# 输出：
# python
```

### ❌ 差的注释：重复代码本身

```python
# 差的注释：这条注释没有提供任何新信息
# 把 favorite_language 转成小写
favorite_language = 'Python'.lower()
```

**类比：** 好的注释就像你在课本上写"这个公式在第3章用过"，差的注释就像你在课本上写"这是公式"——课本上已经写得清清楚楚了。

### 什么时候该写注释？

| 场景 | 示例 |
|------|------|
| 解释复杂的逻辑 | `# 这里用二分查找，因为数据已排序` |
| 记录解决方案的思路 | `# 用字典而不是列表，因为需要快速查找` |
| 标注待完成的任务 | `# TODO: 以后加上错误处理` |
| 说明"为什么"这样做 | `# 用 86400 而不是 24*60*60，因为更直观` |

## 三、Python 之禅与注释

Python 之禅（在终端输入 `import this` 可以看到）中有一条重要的原则：

> **Readability counts.** （可读性很重要）

注释的目的就是让代码更容易理解。好的代码应该"自己能说话"，但有些地方确实需要额外解释。

```python
# ✅ 好的代码 + 好的注释
# 计算圆的面积（公式：π × r²）
radius = 5
area = 3.14159 * radius ** 2
print(area)

# 输出：
# 78.53975
```

## 总结

| 概念 | 说明 | 类比 |
|------|------|------|
| 注释 `#` | 给代码写的便签 | 课本上的铅笔笔记 |
| 好的注释 | 解释"为什么" | "这个公式在第3章用过" |
| 差的注释 | 重复代码本身 | "这是公式"（多余） |
| Python 忽略注释 | 注释不影响程序运行 | 便签不影响课本正文 |
