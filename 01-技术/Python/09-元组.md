# 🔒 Python 元组

## 核心概念

元组 = **不可变的列表**（一旦创建，就不能修改里面的元素）

类比：**元组就像刻在石头上的字** —— 你可以看，但不能改。列表是写在纸上的字，可以擦掉重写。

```python
# 列表用方括号 []
fruits = ['苹果', '香蕉', '橘子']

# 元组用圆括号 ()
dimensions = (200, 50)
```

---

## 一、创建元组

```python
# 创建一个元组
dimensions = (200, 50)

# 访问元素（和列表一样，用索引）
print(dimensions[0])

# 输出：
# 200

print(dimensions[1])

# 输出：
# 50
```

---

## 二、遍历元组

```python
# 用 for 循环遍历元组中的每个元素
dimensions = (200, 50)

for dimension in dimensions:
    print(dimension)

# 输出：
# 200
# 50
```

---

## 三、不能修改元素

```python
dimensions = (200, 50)

# ❌ 尝试修改元组的元素 → 会报错
dimensions[0] = 250

# 输出：
# TypeError: 'tuple' object does not support item assignment
# 翻译：元组不支持修改元素
```

**为什么不能修改？** 这是元组的"保护机制"。就像合同一旦签署，就不能随便修改内容。元组用来存放不应该被改变的数据。

---

## 四、可以重新赋值整个变量

虽然不能修改元组里的元素，但可以把整个变量重新赋值为一个新的元组：

```python
dimensions = (200, 50)
print("Original dimensions:")
for dimension in dimensions:
    print(dimension)

# 输出：
# Original dimensions:
# 200
# 50

# 把变量重新赋值为一个新的元组
dimensions = (400, 100)
print("\nModified dimensions:")
for dimension in dimensions:
    print(dimension)

# 输出：
# Modified dimensions:
# 400
# 100
```

**类比：** 就像你不能修改石头上的字，但你可以换一块新的石头重新刻。

---

## 五、什么时候用元组？

| 场景 | 用元组还是列表？ | 原因 |
|------|-----------------|------|
| 数据不应该被修改 | 元组 | 保护数据不被意外修改 |
| 配置信息 | 元组 | 配置不应该被改变 |
| 需要频繁增删改 | 列表 | 元组不能修改 |
| 作为字典的键 | 元组 | 列表不能作为字典的键 |

```python
# ✅ 用元组存储屏幕分辨率（不应该被修改）
screen_resolution = (1920, 1080)

# ✅ 用列表存储购物车（需要频繁增删改）
shopping_cart = ['苹果', '香蕉', '牛奶']
```

---

## 总结

| 概念 | 说明 | 类比 |
|------|------|------|
| 元组 `()` | 不可变的列表 | 刻在石头上的字 |
| 列表 `[]` | 可变的列表 | 写在纸上的字 |
| 不能修改元素 | 元组的保护机制 | 合同不能随便改 |
| 可以重新赋值 | 换一个新元组 | 换一块新石头 |
