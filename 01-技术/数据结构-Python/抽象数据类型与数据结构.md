# 抽象数据类型与数据结构

## 🗣️ 通俗讲解

> ADT 就像一份「使用说明书」——它只告诉你这个东西能做什么（比如栈能 push 和 pop），但不告诉你里面是怎么实现的。就像你开车只需要知道油门和刹车，不需要知道发动机原理。同一个 ADT 可以有不同的底层实现（数组或链表），但用法一样。

📖 **想看更深入的理论分析？** → [[抽象数据类型ADT]]（邓俊辉 C++ 版）

## 核心概念

### 抽象数据类型（ADT）
- **定义**：数据对象及定义在该对象上的一组操作的数学模型
- **特点**：只定义"做什么"，不定义"怎么做"
- **示例**：列表ADT定义了`append`、`pop`、`insert`等操作，但不指定底层实现

### 信息隐藏
- 将实现细节封装在内部，对外只暴露接口
- 用户无需了解数据如何存储、操作如何实现
- 优势：可修改实现而不影响用户代码

### 数据结构
- **定义**：ADT的具体实现方式
- **关系**：一个ADT可有多种数据结构实现
- **示例**：
  - 列表ADT → 动态数组实现（Python list）
  - 列表ADT → 链表实现

## 关键要点

1. **抽象的价值**：简化问题复杂度，聚焦核心逻辑
2. **接口与实现分离**：同一ADT可有不同性能特性的实现
3. **Python中的体现**：
   - `list`类实现了列表ADT
   - `dict`类实现了字典ADT
   - 用户通过方法调用操作，无需关心底层

## 代码示例

```python
# ADT视角：定义操作接口
class MyList:
    def append(self, item):
        """添加元素到末尾"""
        pass
    
    def pop(self):
        """移除并返回末尾元素"""
        pass

# 用户只需知道接口，无需了解实现细节
my_list = MyList()
my_list.append(1)
my_list.pop()
```
