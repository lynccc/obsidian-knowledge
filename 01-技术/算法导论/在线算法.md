# 在线算法

## 通俗讲解
> 假设你走进一栋楼，想去k楼。你可以等电梯，也可以爬楼梯。问题是：你不知道电梯多久才来。电梯可能1分钟后就到，也可能要等很久。你怎么决定？
>
> 这就是**在线算法**的核心困境：你必须在**不知道未来**的情况下做出决策。在线算法不追求"对某个特定输入最优"，而是追求"在最坏情况下也不会太差"。
>
> **竞争比分析**就像给在线算法打分：不管未来发生什么，你的结果最多比"知道未来的神人"差多少倍？这个"倍数"就是竞争比。

## 核心概念（中文，附英文术语）

### 在线算法 vs 离线算法
- **在线算法（Online Algorithm）**：输入逐步到达，必须即时做出决策，不能撤回
- **离线算法（Offline Algorithm）**：事先知道全部输入，可以全局优化
- **在线算法的挑战**：不知道未来输入，只能基于当前信息决策

### 竞争比（Competitive Ratio）
- **定义**：对于最小化问题，竞争比 = max{A(I)/F(I) : I ∈ U}
  - A(I) = 在线算法在输入I上的代价
  - F(I) = 知道未来的最优算法在输入I上的代价
  - U = 所有可能输入的集合
- **c-竞争（c-competitive）**：竞争比为c，意味着在线算法最多比最优解差c倍
- **竞争比 ≥ 1**，越接近1越好

### 电梯问题的三种策略
1. **总是爬楼梯**：竞争比 = k（电梯马上到时最差）
2. **总是等电梯**：竞争比 = B/k（电梯最慢时最差）
3. **等k分钟，然后爬楼梯**：竞争比 = 2（最优的折中策略）

### 搜索列表维护（List-Maintenance）
- **问题**：维护一个链表，使得搜索操作的总代价最小
- **访问模型（Access Model）**：给定n个元素的链表，搜索x_i的代价 = x_i在链表中的位置
- **换到前面策略（MOVE-TO-FRONT）**：每次搜索到元素后，把它移到链表头部
- **定理**：MOVE-TO-FRONT 是 2-竞争的

### 在线缓存（Online Caching）
- **问题**：缓存只能存放k个数据块，当访问不在缓存中的块时发生缓存缺失（cache miss）
- **LIFO策略**：总是替换最后进入缓存的块
  - 竞争比 = Θ(n/k)
- **LRU策略**（Least Recently Used）：替换最久未使用的块
  - 竞争比 = k（确定性策略的最优下界）
- **MARKING算法**：每轮开始时清除所有标记，访问时标记，替换未标记的块
  - 确定性MARKING竞争比 = 2k-1
- **随机化MARKING**：竞争比 = O(lg k)
  - 这是随机化带来的指数级改进！

### 逆序对（Inversion）分析技巧
- 用于分析MOVE-TO-FRONT的竞争比
- 逆序对：在线算法列表中的一对元素(a,b)，在离线最优算法列表中顺序相反
- 通过逆序对数量的变化来追踪算法的"代价"

## 关键要点

1. **电梯问题的教训**：先等一会儿再切换策略，可以同时抵御两种极端情况
2. **确定性缓存的下界**：任何确定性在线缓存策略的竞争比至少为k（缓存大小）
3. **随机化的力量**：随机化可以将缓存的竞争比从Θ(k)降到O(lg k)
4. **MOVE-TO-FRONT的实用性**：简单有效，2-竞争比，广泛用于实际系统
5. **竞争比 vs 平均情况**：竞争比是**最坏情况**保证，不依赖输入分布
