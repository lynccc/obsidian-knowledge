# B树 (B-Trees) — CLRS 第18章

> **一句话总结**：B树是为磁盘设计的"矮胖"搜索树，每个节点有很多孩子，树高极低，从而减少磁盘访问次数。

---

## 1. 为什么需要 B树？

### 磁盘 vs 内存

| 特性 | 内存 (RAM) | 磁盘 (HDD/SSD) |
|------|-----------|----------------|
| 访问时间 | ~50 纳秒 | ~4 毫秒（HDD） |
| 差距 | — | 慢 5 个数量级！ |
| 数据单位 | 字节/字 | **块**（512B ~ 4KB） |

> **大白话**：访问一次磁盘的时间，够访问内存 10 万次。所以要尽量减少磁盘读写次数。

### B树的优势

- 每个节点包含**多个键**（一个磁盘块大小）
- 分支因子（branching factor）可达 50~2000
- 树高 $h = O(\log_t n)$，其中 $t$ 是最小度数
- **高度 2 的 B树就能存 10 亿个键！**

---

## 2. B树的定义

B树 $T$ 是一棵有根树，满足以下性质：

### 五条性质

1. **每个节点 $x$ 有**：
   - $x.n$：当前存储的键数
   - $x.\text{key}_1 \le x.\text{key}_2 \le \cdots \le x.\text{key}_{x.n}$（有序）
   - $x.\text{leaf}$：是否为叶子

2. **内部节点**有 $x.n + 1$ 个孩子指针 $x.c_1, x.c_2, \ldots, x.c_{x.n+1}$；叶子没有孩子

3. **键分隔子树**：子树 $x.c_i$ 中的所有键 $k$ 满足：
$$x.\text{key}_{i-1} \le k \le x.\text{key}_i$$

4. **所有叶子在同一深度**（等于树高 $h$）

5. **节点键数有界**（用最小度数 $t \ge 2$ 控制）：
   - 除根外，每个节点**至少** $t-1$ 个键（至少 $t$ 个孩子）
   - 每个节点**至多** $2t-1$ 个键（至多 $2t$ 个孩子）
   - 键数恰好 $2t-1$ 时称为**满节点**

### 特例

- $t = 2$：每个内部节点有 2~4 个孩子 → **2-3-4 树**
- 实际中 $t$ 可以很大（比如 1000），大幅降低树高

### 树高定理

**定理 18.1**：$n$ 个键的 B树，高度 $h \le \log_t \frac{n+1}{2}$

> **大白话**：$t = 1000$ 时，高度为 2 的 B树可以存 $2 \times 1000^2 - 1 = 1999999$ 个键（约 200 万）。根节点常驻内存，只需 1 次磁盘访问就能找到任何键。

## 3. B树的基本操作

### 3.1 搜索 (B-TREE-SEARCH)

```
B-TREE-SEARCH(x, k):
    i = 1
    while i ≤ x.n and k > x.key[i]:
        i = i + 1
    if i ≤ x.n and k == x.key[i]:
        return (x, i)          // 找到了
    elseif x.leaf:
        return NIL             // 没找到
    else:
        DISK-READ(x.c[i])
        return B-TREE-SEARCH(x.c[i], k)  // 递归搜索子树
```

- 在每个节点内做**线性搜索**（也可以用二分搜索）
- **磁盘访问**：$O(h) = O(\log_t n)$
- **CPU 时间**：$O(t \log_t n)$

### 3.2 创建 (B-TREE-CREATE)

```
B-TREE-CREATE(T):
    x = ALLOCATE-NODE()
    x.leaf = TRUE
    x.n = 0
    DISK-WRITE(x)
    T.root = x
```

创建一个空的根节点，$O(1)$ 时间。

### 3.3 插入 (B-TREE-INSERT)

#### 核心问题：满了怎么办？

插入到满节点（$2t-1$ 个键）时需要**分裂 (split)**。

#### 分裂操作 (B-TREE-SPLIT-CHILD)

把满节点 $y$（$2t-1$ 个键）从中间分裂：
- 中位键 $y.\text{key}_t$ 上移到父节点
- 左半部分留在 $y$（$t-1$ 个键）
- 右半部分到新节点 $z$（$t-1$ 个键）

```
B-TREE-SPLIT-CHILD(x, i):
    y = x.c[i]           // 要分裂的满子节点
    z = ALLOCATE-NODE()  // 新节点
    z.leaf = y.leaf
    z.n = t - 1
    // 把 y 的后半部分搬到 z
    for j = 1 to t-1:
        z.key[j] = y.key[j+t]
    if not y.leaf:
        for j = 1 to t:
            z.c[j] = y.c[j+t]
    y.n = t - 1
    // 把 z 和中位键插入父节点 x
    for j = x.n downto i:
        x.key[j+1] = x.key[j]
    x.key[i] = y.key[t]     // 中位键上移
    x.n = x.n + 1
    DISK-WRITE(y); DISK-WRITE(z); DISK-WRITE(x)
```

> **大白话**：一个盒子装满了，把中间的东西拿出来给上面的盒子，剩下的一半放新盒子。

#### 插入策略：自顶向下分裂

```
B-TREE-INSERT(T, k):
    r = T.root
    if r.n == 2t - 1:          // 根满了
        s = B-TREE-SPLIT-ROOT(T)
        B-TREE-INSERT-NONFULL(s, k)
    else:
        B-TREE-INSERT-NONFULL(r, k)
```

**关键技巧**：在向下搜索的过程中，**遇到满节点就先分裂**，保证到达叶子时父节点一定不满。

```
B-TREE-INSERT-NONFULL(x, k):
    if x.leaf:
        // 直接插入，把比 k 大的键右移
    else:
        // 找到合适的子节点
        if x.c[i].n == 2t - 1:   // 子节点满了
            B-TREE-SPLIT-CHILD(x, i)  // 先分裂
            // 决定走左边还是右边
        B-TREE-INSERT-NONFULL(x.c[i], k)
```

**时间**：$O(h) = O(\log_t n)$ 次磁盘访问，$O(th) = O(t \log_t n)$ CPU 时间。

**B树只在根节点分裂时才长高**。

## 4. B树的删除 (B-TREE-DELETE)

删除比插入更复杂，因为要保证删除后每个节点（除根外）至少有 $t-1$ 个键。

### 核心策略

**保证递归调用时节点至少有 $t$ 个键**（比最低要求多 1），这样删掉一个后仍然合法。

### 三种情况

#### Case 1：键在叶子中
直接删除（如果叶子至少有 $t$ 个键）。

#### Case 2：键在内部节点中
分三种子情况：

- **Case 2a**：左孩子有 $\ge t$ 个键 → 用**前驱**替换，递归删前驱
- **Case 2b**：右孩子有 $\ge t$ 个键 → 用**后继**替换，递归删后继
- **Case 2c**：左右孩子都只有 $t-1$ 个键 → **合并**两个孩子，然后递归删除

#### Case 3：键不在当前内部节点中
确保要下降的子节点至少有 $t$ 个键：
- 如果兄弟有 $\ge t$ 个键 → **借一个**过来（旋转）
- 如果兄弟也只有 $t-1$ 个键 → **合并**当前节点和兄弟

> **大白话**：删除就像"借东西"——如果要走的那条路的节点太"瘦"，先从兄弟那借一个，或者跟兄弟合并，保证路上不会出现太瘦的节点。

**时间**：$O(h) = O(\log_t n)$ 次磁盘访问。

---

## 5. B+树 (B+-tree) 简介

B+树是 B树的一个重要变体：
- **所有卫星数据只存在叶子节点**
- 内部节点只存键和孩子指针
- 叶子节点用链表串联
- 这样内部节点的分支因子更大 → 树更矮

---

## 6. B树 vs 红黑树

| 特性 | B树 | 红黑树 |
|------|-----|--------|
| 设计目标 | 减少磁盘访问 | 内存中高效操作 |
| 节点 | 多键（一个磁盘块） | 单键 |
| 树高 | $O(\log_t n)$，$t$ 可很大 | $O(\log n)$ |
| 每次操作磁盘访问 | $O(\log_t n)$ | — |
| 平衡方式 | 分裂/合并 | 旋转 + 重新着色 |
| 应用 | 数据库索引、文件系统 | 内存中的有序集合 |
