# 贪心算法 (Greedy Algorithms) — CLRS 第15章

> **一句话总结**：贪心算法在每一步都选"眼前最好"的，不回头，不后悔，如果问题满足贪心选择性质和最优子结构，就能得到全局最优解。

---

## 1. 活动选择问题 (Activity-Selection Problem)

### 问题描述

有 $n$ 个活动 $S = \{a_1, a_2, \ldots, a_n\}$，每个活动 $a_i$ 有开始时间 $s_i$ 和结束时间 $f_i$。同一时间只能进行一个活动。求**最多能选多少个兼容活动**。

两个活动兼容：$[s_i, f_i)$ 和 $[s_j, f_j)$ 不重叠，即 $s_i \ge f_j$ 或 $s_j \ge f_i$。

### 贪心策略

**总是选最早结束的活动**，然后排除与之冲突的，重复此过程。

> **大白话**：会议室一天只能借一个活动，你想安排最多活动。直觉：先借给最早结束的，这样剩下的时间最多，能安排更多活动。

### 为什么贪心是对的？

**定理 15.1**：设 $a_m$ 是子问题 $S_k$ 中最早结束的活动，则 $a_m$ 一定属于某个最大兼容活动集。

**证明思路**（剪切-粘贴 / exchange argument）：
1. 设 $A_k$ 是最优解，$a_j$ 是其中最早结束的活动
2. 如果 $a_j \ne a_m$，把 $a_j$ 换成 $a_m$
3. 因为 $f_m \le f_j$，$a_m$ 与 $A_k$ 中其他活动仍然兼容
4. 所以 $A_k' = (A_k - \{a_j\}) \cup \{a_m\}$ 也是最优解，且包含 $a_m$ ✓

### 递归版本

```
RECURSIVE-ACTIVITY-SELECTOR(s, f, k, n):
    m = k + 1
    while m ≤ n and s[m] < f[k]:  // 找第一个兼容的活动
        m = m + 1
    if m ≤ n:
        return {a_m} ∪ RECURSIVE-ACTIVITY-SELECTOR(s, f, m, n)
    else return ∅
```

### 迭代版本

```
GREEDY-ACTIVITY-SELECTOR(s, f, n):
    A = {a_1}
    k = 1
    for m = 2 to n:
        if s[m] ≥ f[k]:   // 兼容？
            A = A ∪ {a_m}
            k = m
    return A
```

**时间复杂度**：$O(n)$（假设已按结束时间排序；否则先排序，总时间 $O(n \log n)$）

## 2. 贪心算法的两大要素

### 贪心选择性质 (Greedy-choice Property)

> 可以通过**局部最优选择**（不考虑子问题的解）构造出**全局最优解**。

- DP：先解子问题，再做选择（自底向上）
- 贪心：先做选择，再解剩下的子问题（自顶向下）

**大白话**：贪心的核心问题 — "我现在选最好的，后面的事交给后面处理，会不会搞砸全局？" 如果不会，就有贪心选择性质。

### 最优子结构 (Optimal Substructure)

> 问题的最优解包含其子问题的最优解。

这个性质 DP 和贪心都要求，是能用这两种方法的前提。

### 贪心算法设计步骤

1. 将问题转化为：做一个选择，剩下一个子问题
2. 证明存在一个最优解包含贪心选择（贪心选择性质）
3. 证明贪心选择 + 子问题最优解 = 原问题最优解（最优子结构）

### 贪心 vs DP

| 特性 | 贪心 | 动态规划 |
|------|------|----------|
| 选择 | 只看一个（贪心选择） | 考虑所有可能 |
| 子问题数 | 1 个 | 多个重叠子问题 |
| 求解顺序 | 自顶向下 | 自底向上 / 备忘录 |
| 效率 | 通常更快 | 可能较慢 |
| 正确性 | 需要证明 | 通常更可靠 |

> **大白话**：贪心是"一条路走到黑"，DP 是"把所有路都试一遍"。贪心快但不一定对，DP 慢但保证对。

## 3. 赫夫曼编码 (Huffman Codes)

详见 → [[Huffman编码]]

### 核心思想

- 用**变长编码**：高频字符用短编码，低频字符用长编码
- 要求**前缀码**（prefix-free code）：任何编码都不是另一个编码的前缀
- 用**二叉树**表示编码：左走 = 0，右走 = 1

### 贪心策略

每次合并**频率最小的两棵树**：

```
HUFFMAN(C):
    n = |C|
    Q = 以频率为key的最小优先队列，初始化为C中的所有字符
    for i = 1 to n-1:
        z = ALLOCATE-NODE()
        z.left = x = EXTRACT-MIN(Q)   // 频率最小的
        z.right = y = EXTRACT-MIN(Q)  // 第二小的
        z.freq = x.freq + y.freq
        INSERT(Q, z)
    return EXTRACT-MIN(Q)  // 返回根节点
```

**时间复杂度**：$O(n \log n)$（用最小堆）

### 正确性证明要点

1. **贪心选择性质**：频率最低的两个字符一定在最优编码树的最深层，且互为兄弟
2. **最优子结构**：合并后的子问题（$n-1$ 个字符）的最优解 + 合并操作 = 原问题最优解

> **大白话**：就像压缩文件 — a 出现 45000 次只用 1 位编码（0），f 出现 5000 次用 4 位（1100）。总共省了 76000 位！

## 4. 贪心不适用的情况

### 0-1 背包问题

贪心（按价值密度排序）**不能**得到最优解！

**反例**：容量 50 的背包
| 物品 | 重量 | 价值 | 密度 |
|------|------|------|------|
| 1 | 10 | 60 | 6.0 |
| 2 | 20 | 100 | 5.0 |
| 3 | 30 | 120 | 4.0 |

- 贪心选物品1（密度最高）→ 价值 60，剩余容量 40，只能选物品2的一部分（如果允许分数）
- 但选物品2+3 = 价值 220（如果只能选整数个）

> **0-1 背包**需要 DP，**分数背包**（可以拿一部分）可以用贪心。

## 5. 离线缓存问题 (Offline Caching)

### 问题

缓存容量为 $k$，给定一个访问序列，求最小缓存未命中次数。

### 贪心策略：Belady's Algorithm

当需要驱逐时，**驱逐下次使用时间最远的那个缓存项**。

**定理 15.5**：Belady 算法对离线缓存问题是最优的。

> **大白话**：你有 3 个格子的缓存，要淘汰一个。看看哪个东西最晚才会被用到，就淘汰它。
