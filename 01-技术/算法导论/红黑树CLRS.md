# 红黑树（Red-Black Trees）

## 通俗讲解
> 红黑树是一种"聪明"的二叉搜索树，它给每个节点涂上红色或黑色，通过一些着色规则来保证树不会变得太歪斜。就像交通规则让道路保持畅通一样，红黑树的规则让搜索、插入、删除都能在 O(log n) 时间内完成。
>
> 你可以把红黑树想象成一棵"有纪律"的 BST：它不允许某个分支长得太长（超过其他分支的两倍），通过"旋转"操作来调整结构，保持平衡。

## 核心概念（中文，附英文术语）

### 红黑树的五条性质（Properties）

红黑树是满足以下五条性质的[[二叉搜索树CLRS]]：

1. **每个节点是红色或黑色**（Every node is either RED or BLACK）
2. **根节点是黑色**（The root is BLACK）
3. **每个叶子节点（NIL）是黑色**（Every leaf/NIL is BLACK）
4. **红色节点的两个孩子都是黑色**（If a node is RED, both children are BLACK）
   - → 没有两个连续的红色节点
5. **从任一节点到其所有后代叶子的简单路径上，包含相同数目的黑色节点**（All simple paths from a node to descendant leaves have the same number of black nodes）
   - → **黑高**（black-height）相同

**关键推论**：
- 性质 4 和 5 保证：**没有路径比其他路径长两倍以上**
- 红黑树的高度 h ≤ 2 lg(n+1)（见引理 13.1）
- 因此所有操作都是 **O(log n)**

### 哨兵（Sentinel）
使用一个全局的黑色哨兵节点 `T.nil` 代替所有 NIL 指针：
- 简化边界条件处理
- 哨兵的属性与普通节点相同，但颜色固定为黑色

### 黑高（Black Height）
节点 x 的黑高 bh(x) 是从 x 到叶子的任意简单路径上黑色节点的数量（不包括 x 本身）。

**引理**：以 x 为根的子树中，内部节点数至少为 2^{bh(x)} - 1。

### 旋转（Rotations）

旋转是红黑树的基本操作，用于在插入和删除后恢复红黑性质，同时保持 BST 性质。

#### 左旋（LEFT-ROTATE）
```
LEFT-ROTATE(T, x):
    y = x.right           // y 是 x 的右孩子
    x.right = y.left      // 将 y 的左子树变为 x 的右子树
    if y.left ≠ T.nil:
        y.left.p = x
    y.p = x.p              // 将 y 连接到 x 的父节点
    if x.p == T.nil:
        T.root = y
    elif x == x.p.left:
        x.p.left = y
    else:
        x.p.right = y
    y.left = x              // 将 x 放到 y 的左边
    x.p = y
```

#### 右旋（RIGHT-ROTATE）
对称操作。

**关键性质**：
- 旋转是 **O(1)** 操作
- 旋转保持 BST 的中序遍历顺序不变
- 旋转只改变常数个指针

**直觉**：左旋把右孩子"提上来"，右旋把左孩子"提上来"。

### 插入（Insertion）

插入一个新节点 z 的过程：

#### 第一阶段：像普通 BST 一样插入
1. 找到插入位置
2. 将 z 作为叶子节点插入
3. **将 z 着色为红色**（为什么？因为着色为红色可能违反性质 4，但不会违反性质 5）

#### 第二阶段：修复红黑性质（RB-INSERT-FIXUP）
可能违反的性质：
- **性质 2**：如果 z 是根节点
- **性质 4**：如果 z 的父节点也是红色

**修复策略**：通过重新着色和旋转，将"红色违规"向上传播，直到根节点或不再违规。

#### 三种情况（假设 z 的父节点是左孩子）：

**情况 1：z 的叔叔是红色**
```
z.p.color = BLACK      // 父节点变黑
uncle.color = BLACK    // 叔叔变黑
grandparent.color = RED // 祖父变红
z = grandparent        // 继续向上检查
```

**情况 2：z 的叔叔是黑色，z 是右孩子**
```
z = z.p
LEFT-ROTATE(T, z)      // 转换为情况 3
```

**情况 3：z 的叔叔是黑色，z 是左孩子**
```
z.p.color = BLACK      // 父节点变黑
grandparent.color = RED // 祖父变红
RIGHT-ROTATE(T, grandparent) // 右旋
```

**时间复杂度**：O(log n)
- 第一阶段：O(log n) 向下遍历
- 第二阶段：O(log n) 向上修复，最多 2 次旋转

**关键性质**：插入后最多需要 **2 次旋转**！

---

### 删除（Deletion）

删除比插入更复杂，需要考虑更多情况。

#### 第一阶段：像普通 BST 一样删除
1. 找到要删除的节点 z
2. 确定实际被删除的节点 y（z 或 z 的后继）
3. 确定 y 的替代节点 x
4. 用 x 替换 y 的位置

#### 第二阶段：修复红黑性质（RB-DELETE-FIXUP）
如果被删除的节点 y 是黑色，删除后会违反性质 5（某条路径上的黑高减少）。

**修复策略**：将"额外的黑色"向上传播，直到根节点或遇到红色节点。

#### 四种情况（假设 x 是左孩子）：

**情况 1：x 的兄弟 w 是红色**
- 将 w 变黑，父节点变红
- 对父节点左旋
- 转换为情况 2、3 或 4

**情况 2：x 的兄弟 w 是黑色，w 的两个孩子都是黑色**
- 将 w 变红
- x = x.p（向上传播）
- 如果 x 是红色，结束；否则继续

**情况 3：x 的兄弟 w 是黑色，w 的左孩子是红色，右孩子是黑色**
- 将 w 的左孩子变黑，w 变红
- 对 w 右旋
- 转换为情况 4

**情况 4：x 的兄弟 w 是黑色，w 的右孩子是红色**
- w 的颜色 = x.p 的颜色
- x.p 变黑，w 的右孩子变黑
- 对 x.p 左旋
- 结束

**时间复杂度**：O(log n)
- 第一阶段：O(log n)
- 第二阶段：O(log n)，最多 **3 次旋转**

## 红黑树的性能

| 操作 | 时间复杂度 | 旋转次数 |
|------|-----------|---------|
| 搜索 | O(log n) | 0 |
| 插入 | O(log n) | 最多 2 次 |
| 删除 | O(log n) | 最多 3 次 |
| 最小/最大 | O(log n) | 0 |
| 前驱/后继 | O(log n) | 0 |

## 红黑树 vs AVL 树

| 特性 | 红黑树 | AVL 树 |
|------|--------|--------|
| 平衡条件 | 较宽松（h ≤ 2lg(n+1)） | 较严格（左右子树高差 ≤ 1） |
| 插入旋转 | 最多 2 次 | 最多 2 次 |
| 删除旋转 | 最多 3 次 | O(log n) 次 |
| 搜索 | 略慢（树可能更高） | 略快 |
| 插入/删除 | 更快（旋转少） | 较慢 |
| 实际应用 | 更常用（如 Linux 内核、Java TreeMap） | 较少用 |

## 关键要点

1. **五条性质保证平衡**：树高不超过 2 lg(n+1)
2. **旋转是核心操作**：O(1) 时间改变树结构，保持 BST 性质
3. **插入比删除简单**：插入最多 2 次旋转，删除最多 3 次
4. **红色传播 vs 黑色传播**：插入时红色违规向上传播，删除时黑色违规向上传播
5. **哨兵简化代码**：统一处理 NIL 边界条件
