# 散列表（Hash Tables）

## 通俗讲解
> 散列表就像一个超级高效的通讯录。你想找"张三"的电话号码，不需要从头翻到尾，而是通过一个公式（散列函数）直接算出"张三"应该在第几页，然后翻到那一页就能找到。
>
> 但有时候两个名字会算出相同的页码（冲突），就像两个人同时被安排到同一个座位。解决方法有两种：
> - **链地址法**：在这个座位上放一条链表，把所有被安排到这里的人串起来
> - **开放寻址**：如果座位被占了，就去找下一个空座位

## 核心概念（中文，附英文术语）

### 直接寻址表（Direct-Address Table）

当键的范围 U = {0, 1, ..., m-1} 较小时，直接用数组 T[0..m-1] 存储：
- T[k] 存储键为 k 的元素
- 搜索、插入、删除都是 O(1)

**缺点**：当 U 很大时（如 64 位整数），数组太大，无法分配。

---

### 散列表（Hash Tables）

**核心思想**：用散列函数 h 将键 k 映射到数组 T 的下标 h(k)，数组大小 m 远小于 |U|。

```
存储元素 x → T[h(x.key)]
搜索键 k   → 在 T[h(k)] 处查找
```

#### 冲突（Collision）
不同的键可能映射到相同的槽位：h(k₁) = h(k₂)

**解决方案**：
1. **链地址法（Chaining）**：每个槽位存一个链表
2. **开放寻址（Open Addressing）**：冲突时探测其他槽位

---

### 链地址法（Chaining）

每个槽位 T[j] 指向一个链表，存储所有 h(k) = j 的元素。

```
CHAINED-HASH-INSERT(T, x):
    LIST-PREPEND(T[h(x.key)], x)

CHAINED-HASH-SEARCH(T, k):
    return LIST-SEARCH(T[h(k)], k)

CHAINED-HASH-DELETE(T, x):
    LIST-DELETE(T[h(x.key)], x)
```

#### 性能分析
设 n = 元素数量，m = 槽位数量，**装载因子** α = n/m（每个链表的平均长度）

| 操作 | 最坏情况 | 期望（均匀散列） |
|------|---------|-----------------|
| 搜索 | Θ(n) | Θ(1 + α) |
| 插入 | Θ(1) | Θ(1) |
| 删除 | Θ(n) | Θ(1 + α) |

**关键结论**：如果 m = Θ(n)，则 α = O(1)，所有操作期望 O(1)！

---

### 散列函数（Hash Functions）

#### 除法散列法（Division Method）
```
h(k) = k mod m
```
- m 的选择很重要：避免 m 是 2 的幂，选择不太接近 2 的幂的素数

#### 乘法散列法（Multiplication Method）
```
h(k) = ⌊m · (kA mod 1)⌋
```
- A 是常数，通常取 (√5 - 1)/2 ≈ 0.6180（黄金比例）
- 优点：对 m 的选择不太敏感

#### 全域散列（Universal Hashing）
**核心思想**：随机选择散列函数，而不是使用固定的散列函数。

**定义**：散列函数族 ℋ 是全域的，如果对任意两个不同的键 k₁ ≠ k₂：
```
Pr_{h∈ℋ}[h(k₁) = h(k₂)] ≤ 1/m
```

**优势**：即使对手知道算法，也无法构造使所有键冲突的输入。

#### 完美散列（Perfect Hashing）
当所有键已知时（静态集合），可以构造无冲突的散列函数，实现最坏情况 O(1) 搜索。

---

### 开放寻址（Open Addressing）

所有元素都存在散列表中，不使用链表。冲突时按**探测序列**寻找下一个空槽位。

```
HASH-INSERT(T, k):
    i = 0
    repeat:
        q = h(k, i)
        if T[q] == NIL:
            T[q] = k
            return q
        i = i + 1
    until i == m
    error "overflow"

HASH-SEARCH(T, k):
    i = 0
    repeat:
        q = h(k, i)
        if T[q] == k:
            return q
        i = i + 1
    until T[q] == NIL or i == m
    return NIL
```

#### 探测技术

**线性探测（Linear Probing）**
```
h(k, i) = (h'(k) + i) mod m
```
- 问题：**一次聚集**（primary clustering）—— 连续被占用的槽位会越来越长

**二次探测（Quadratic Probing）**
```
h(k, i) = (h'(k) + c₁i + c₂i²) mod m
```
- 问题：**二次聚集**（secondary clustering）

**双重散列（Double Hashing）**
```
h(k, i) = (h₁(k) + i · h₂(k)) mod m
```
- 最好的开放寻址方法
- h₂(k) ≠ 0，且 h₂(k) 与 m 互素

#### 性能分析
设 α = n/m < 1（装载因子必须小于 1）

| 操作 | 期望探测次数（均匀散列） |
|------|------------------------|
| 成功搜索 | 1/α · ln(1/(1-α)) |
| 不成功搜索 | 1/(1-α) |

当 α = 0.5 时，成功搜索约 1.39 次，不成功搜索约 2 次。
当 α = 0.9 时，成功搜索约 2.56 次，不成功搜索约 10 次。

### 实际考虑

#### 删除操作
开放寻址中删除不能简单置 NIL，否则会中断探测链。

**解决方案**：
- 使用 DELETED 标记（增加搜索时间）
- 线性探测的特殊删除方法：将后续需要移动的元素前移

#### 缓存友好的散列表
- **线性探测**：虽然理论性能差，但缓存命中率高，实践中可能更快
- 使用 2-独立散列函数（如基于多项式的散列）

## 散列表 vs 其他数据结构

| 特性 | 散列表 | BST | 有序数组 |
|------|--------|-----|---------|
| 搜索（平均） | O(1) | O(log n) | O(log n) |
| 搜索（最坏） | O(n) | O(log n)（平衡BST） | O(log n) |
| 插入（平均） | O(1) | O(log n) | O(n) |
| 有序遍历 | 不支持 | O(n) | O(n) |
| 空间 | O(n) | O(n) | O(n) |

## 关键要点

1. **期望 O(1)**：在合理假设下，散列表的所有操作都是常数时间
2. **散列函数设计**：好的散列函数应该近似均匀分布
3. **装载因子**：链地址法 α 可以 > 1，开放寻址 α 必须 < 1
4. **随机化**：全域散列通过随机选择散列函数避免最坏情况
5. **缓存效率**：开放寻址（尤其线性探测）通常比链地址法更缓存友好
