# 并行算法基础

## 通俗讲解
> 想象你是一个厨师，需要做一桌菜。如果你一个人按顺序做，每道菜花10分钟，8道菜就要80分钟。但如果你有4个帮手，你可以同时让他们各做一道菜，时间就缩短到20分钟。这就是并行算法的核心思想——**把大任务拆成可以同时执行的小任务**。
>
> 但并行没那么简单：有些任务之间有依赖关系（比如必须先切菜才能炒菜），你不能随便并行。Fork-join模型就是帮我们管理这种"哪些能同时做、哪些必须等"的编程框架。

## 核心概念（中文，附英文术语）

### Fork-Join 并行模型
- **Fork（派生）**：创建子任务，父任务可以继续执行而不等待子任务完成（不同于普通的函数调用）
- **Join（汇合）**：等待所有派生的子任务完成后，父任务才能继续
- **Spawn（生成）**：Fork操作在伪代码中的关键字
- **Sync（同步）**：Join操作，等待所有子任务完成
- **串行投影（Serial Projection）**：去掉并行关键字后，剩下的就是普通的串行算法

### 三个并行关键字
1. `parallel` —— 标记可并行执行的循环
2. `spawn` —— 标记可并行执行的子过程调用
3. `sync` —— 等待所有子任务完成

### 工作量与跨度（Work and Span）
- **工作量 T₁**：所有任务的总计算量（假设只有1个处理器时的运行时间）
- **跨度 T∞**：最长依赖链的长度（无限处理器时的运行时间，即关键路径）
- **并行度（Parallelism）**：T₁/T∞，表示平均可以同时执行的任务数
- **P个处理器的运行时间 Tₚ**：满足 T₁/P ≤ Tₚ ≤ T₁

### 调度定理
- **贪婪调度（Greedy Scheduler）**：每个处理器只要有任务就执行
- **定理**：Tₚ ≤ T₁/P + T∞
  - T₁/P 反映负载均衡
  - T∞ 反映固有的串行瓶颈

### 并行计算的DAG模型
- 计算过程可以表示为有向无环图（DAG）
- 顶点 = 任务链（strand）
- 边 = 依赖关系
- 并行 = 没有依赖关系的顶点可以同时执行

## 关键要点

1. **三个关键词**：`parallel`、`spawn`、`sync` 是fork-join并行的核心
2. **工作量定律**：Tₚ ≥ T₁/P（P个处理器不可能比串行快超过P倍）
3. **跨度定律**：Tₚ ≥ T∞（即使无限处理器，也不能比关键路径更快）
4. **调度上界**：Tₚ ≤ T₁/P + T∞（贪婪调度的性能保证）
5. **并行归并排序**：工作量 O(n lg n)，跨度 O(lg²n)，并行度 O(n/lg²n)
6. **确定性竞争（Determinacy Race）**：多个并行任务同时读写同一变量导致结果不确定

### 并行归并排序的关键思想
- 使用[[分治法]]，递归地对两半并行排序
- 归并操作通过二分搜索找到分割点，实现O(lg n)跨度
- 总工作量 T₁(n) = O(n lg n)，与串行版本相同
- 跨度 T∞(n) = O(lg²n)

## 与其他概念的联系
- 并行归并排序是[[堆排序]]和[[快速排序]]的并行版本对比
- 工作量/跨度分析类似于[[渐进记号CLRS]]中的O记号思想
- fork-join模型是[[分治法]]的自然并行化
- 并行矩阵乘法利用了矩阵的分块结构
