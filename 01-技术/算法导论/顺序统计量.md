# 中位数和顺序统计量（Medians and Order Statistics）

## 通俗讲解
> 顺序统计量就是"第 i 小的数"。比如：
> - 第 1 小的数 = 最小值
> - 第 n 小的数 = 最大值
> - 第 ⌊(n+1)/2⌋ 小的数 = 中位数
>
> 最简单的找第 i 小元素的方法是先排序，然后取第 i 个，但这需要 O(n log n) 时间。有趣的是，我们可以用 **O(n)** 时间完成这个任务！就像快速排序的分区思想，但不需要对两边都递归——只递归一边就够了。

## 核心概念（中文，附英文术语）

### 最小值和最大值（Minimum and Maximum）

#### 找最小值
```
MINIMUM(A, n):
    min = A[1]
    for i = 2 to n:
        if min > A[i]:
            min = A[i]
    return min
```
**比较次数**：n - 1 次

**下界**：任何找最小值的算法都需要至少 n - 1 次比较（锦标赛模型证明：每个非最小元素至少输一次）。

#### 同时找最小值和最大值
**技巧**：成对处理元素，先比较两个元素，再把较小的和当前最小值比，较大的和当前最大值比。

**比较次数**：最多 ⌊3n/2⌋ 次（比分别找最小和最大节省了约 25% 的比较）

```
如果 n 是奇数：min = max = A[1]，处理剩下 n-1 个元素（偶数个）
如果 n 是偶数：比较 A[1] 和 A[2]，初始化 min 和 max

对于每对元素 (A[2i], A[2i+1]):
1. 先比较两个元素（1 次比较）
2. 较小的和 min 比（1 次比较）
3. 较大的和 max 比（1 次比较）

每对元素需要 3 次比较，共 ⌊n/2⌋ 对
总计：3⌊n/2⌋ 次比较
```

### 期望线性时间的选择算法（RANDOMIZED-SELECT）

**核心思想**：类似快速排序的分区，但只递归处理一边！

```
RANDOMIZED-SELECT(A, p, r, i):
    if p == r:
        return A[p]
    q = RANDOMIZED-PARTITION(A, p, r)
    k = q - p + 1                    // 枢轴是第 k 小的元素
    if i == k:
        return A[q]                  // 枢轴就是我们要找的
    elseif i < k:
        return RANDOMIZED-SELECT(A, p, q-1, i)   // 在左边找
    else:
        return RANDOMIZED-SELECT(A, q+1, r, i-k) // 在右边找
```

**关键区别**：
- 快速排序：递归处理**两边** → 期望 Θ(n log n)
- 选择算法：只递归处理**一边** → 期望 Θ(n)

#### 分析
**最坏情况**：Θ(n²) —— 每次分区都极不平衡

**期望运行时间**：Θ(n)

**直觉**：假设每次随机选的枢轴落在元素的"中间一半"（第二和第三个四分位数），那么每次至少有 1/4 的元素被丢弃，递归深度为 O(log n)，每层做 O(n) 工作。

**严格分析**：
设指示器随机变量 X_k 表示大小为 k 的子问题是否被创建。
- 子问题大小 k 的范围：1 到 n
- E[X_k] ≤ 2/(k+1)（枢轴落在"好"位置的概率）

E[T(n)] = Σ_{k=1}^{n} E[X_k] · O(k)
        = O(n · Σ_{k=1}^{n} 1/(k+1))
        = O(n · ln n)
        = O(n log n)

实际上，通过更仔细的分析，可以证明期望运行时间是 **Θ(n)**。

### 最坏情况线性时间的选择算法（SELECT）

**核心思想**：通过"中位数的中位数"（median of medians）来选择一个好的枢轴。

#### 算法步骤
```
SELECT(A, p, r, i):
    1. 将 n 个元素分成 ⌊n/5⌋ 组，每组 5 个元素
    2. 找出每组的中位数（共 ⌊n/5⌋ 个中位数）
    3. 递归地找出这些中位数的中位数 x（作为枢轴）
    4. 用 x 对数组进行分区
    5. 根据枢轴的位置，递归处理一边
```

#### 为什么是线性时间？

**关键观察**：中位数的中位数 x 是一个"好"枢轴：
- 至少有 ⌊n/5⌋/2 = ⌈n/10⌉ 个中位数 ≤ x
- 每个这样的中位数对应 3 个 ≤ 它的元素
- 因此至少有 3⌈n/10⌉ 个元素 ≤ x

类似地，至少有 3⌈n/10⌉ 个元素 ≥ x。

**所以分区后，两边最多有 7n/10 个元素！**

**递归关系**：
```
T(n) ≤ T(⌈n/5⌉) + T(7n/10) + O(n)
```

通过主定理或代入法可证 T(n) = O(n)。

#### 实际考虑
虽然 SELECT 在理论上是线性的，但由于常数因子较大，实践中 RANDOMIZED-SELECT 更受欢迎。

## 选择算法对比

| 算法 | 期望时间 | 最坏情况时间 | 空间 | 实践性能 |
|------|---------|-------------|------|---------|
| 排序后取第 i 个 | O(n log n) | O(n log n) | O(n) | 慢 |
| RANDOMIZED-SELECT | O(n) | O(n²) | O(log n) | 快 |
| SELECT（中位数的中位数） | O(n) | O(n) | O(n) | 较慢 |

## 关键要点

1. **找最小值需要 n-1 次比较**：这是下界，无法改进
2. **同时找最小最大只需 ⌊3n/2⌋ 次**：成对处理的技巧
3. **选择问题可以在 O(n) 时间内解决**：比排序更快
4. **随机化版本更实用**：期望线性时间，常数因子小
5. **中位数的中位数保证最坏情况线性**：但常数因子大，实践中少用
