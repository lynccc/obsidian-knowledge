# NP完全性

## 通俗讲解
> 在算法世界里，有些问题很容易（比如排序），有些问题看起来很难（比如旅行商问题）。但"难"到底有多难？有没有可能只是我们还没找到好算法？
>
> **P vs NP** 问题是计算机科学最著名的未解之谜。简单来说：
> - **P** = 能快速求解的问题（多项式时间）
> - **NP** = 能快速验证答案的问题
> - **NP完全** = NP中最难的一类问题
>
> 关键问题是：**P = NP 吗？** 即，所有能快速验证答案的问题，是否都能快速求解？大多数科学家认为 P ≠ NP，但这至今未被证明。
>
> 打个比方：考试时，做一道数学题可能很难，但验证一个答案是否正确通常很容易。P = NP 意味着"做题和验题一样容易"——这看起来不太可能，但我们无法证明。

## 核心概念（中文，附英文术语）

### 三个复杂性类

#### P类（Polynomial Time）
- **定义**：能在多项式时间内**求解**的判定问题集合
- **例子**：排序、最短路径、最大流、二分图匹配
- **直觉**：这些问题是"易解的"（tractable）

#### NP类（Nondeterministic Polynomial Time）
- **定义**：能在多项式时间内**验证**一个解是否正确的判定问题集合
- **关键概念**——**证书（Certificate）**：
  - 对于NP问题，如果给你一个"候选答案"（证书），你能在多项式时间内验证它是否正确
  - 例：哈密顿回路问题——给你一个顶点序列，你可以在O(n)时间内验证它是否是合法的哈密顿回路
- **P ⊆ NP**：如果一个问题能快速求解，当然也能快速验证
- **核心问题**：P ⊂ NP 还是 P = NP？

#### NP完全类（NPC, NP-Complete）
- **定义**：一个问题L是NP完全的，如果：
  1. L ∈ NP
  2. NP中的每个问题都可以**多项式时间归约**到L
- **直觉**：NPC问题是NP中"最难"的问题
- **关键性质**：如果任何一个NPC问题有多项式时间算法，则所有NP问题都有（即P = NP）

### 多项式时间归约（Polynomial-Time Reduction）
- **定义**：问题A可以多项式时间归约到问题B（写作 A ≤_P B），如果存在一个多项式时间函数f：
  - 把A的任何实例α转换为B的一个实例β
  - α的答案是"是" ⟺ β的答案是"是"
- **用途**：
  - 如果B很容易，则A也很容易（通过先转换再求解）
  - 如果A很难，则B也很难（反证法）
- **证明NPC的方法**：
  1. 证明L ∈ NP（给个验证算法）
  2. 从一个已知的NPC问题归约到L

### 决策问题 vs 优化问题
- **决策问题（Decision Problem）**：答案是"是"或"否"
- **优化问题（Optimization Problem）**：找最优解
- NP完全性理论针对决策问题，但可以扩展到优化问题
- 例：最短路径（优化）→ 路径长度≤k？（决策）

### 经典NP完全问题

#### 电路可满足性（Circuit Satisfiability）
- **第一个被证明NP完全的问题**（Cook-Levin定理）
- 给定一个布尔电路，是否存在输入使得输出为1？

#### 3-CNF可满足性（3-SAT）
- 给定一个3-CNF布尔公式（每个子句恰好3个文字的AND of ORs），是否存在满足赋值？
- 从电路可满足性归约而来
- **注意**：2-SAT在P中，3-SAT是NPC——从2到3，难度质变！

#### 团问题（Clique）
- 给定图G和整数k，是否存在k个顶点两两相连？
- 从3-SAT归约而来

#### 顶点覆盖（Vertex Cover）
- 给定图G和整数k，是否存在k个顶点覆盖所有边？
- 从团问题归约而来

#### 哈密顿回路（Hamiltonian Cycle）
- 给定图G，是否存在经过每个顶点恰好一次的回路？
- 从顶点覆盖归约而来

#### 旅行商问题（TSP, Traveling Salesperson Problem）
- 给定完全图和边权，是否存在总权重≤k的哈密顿回路？
- 从哈密顿回路归约而来

#### 子集和（Subset Sum）
- 给定整数集合S和目标值t，是否存在子集的和恰好为t？
- 从3-CNF可满足性归约而来

### 归约链
```
电路可满足性 → 3-SAT → 团问题 → 顶点覆盖 → 哈密顿回路 → TSP
                                                          ↓
                              3-SAT → 子集和 ──────────────┘
```

## 关键要点

1. **P vs NP 的核心含义**：求解和验证的难度是否对等？
2. **NP完全的意义**：如果找到任何一个NPC问题的多项式算法，P = NP
3. **归约是证明的核心**：通过归约链，一个NPC问题的硬度"传递"给所有后续问题
4. **实际影响**：证明一个问题是NP完全的，就不要浪费时间找精确的多项式算法了——转而寻找近似算法或特殊情形的算法
5. **2-SAT vs 3-SAT**：从2到3，问题从P跳到NPC，这是复杂性的"相变"
6. **大多数人相信 P ≠ NP**：但这是未证明的猜想

### NP完全问题的应对策略
1. **近似算法**：接受不精确但快速的解（见[[近似算法]]）
2. **启发式算法**：实际中表现好的非精确算法
3. **参数化算法**：对问题的某个参数是指数级，但对输入大小是多项式
4. **特殊情况**：限制输入结构，使问题变得易解
5. **随机化算法**：用随机性换取效率
