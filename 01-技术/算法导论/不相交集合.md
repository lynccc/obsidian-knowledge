# 不相交集合的数据结构 (Disjoint Sets / Union-Find) — CLRS 第19章

> **一句话总结**：并查集（Union-Find）是一种管理"分组"的数据结构，支持合并集合和查询元素所属集合，用了按秩合并+路径压缩后，每次操作几乎 $O(1)$。

---

## 1. 基本概念

### 不相交集合

一组互不相交的动态集合 $S = \{S_1, S_2, \ldots, S_k\}$，每个集合用一个**代表元素**（representative）标识。

### 三种操作

| 操作 | 说明 | 大白话 |
|------|------|--------|
| `MAKE-SET(x)` | 创建只包含 $x$ 的新集合 | 给 $x$ 开一个新组 |
| `UNION(x, y)` | 合并包含 $x$ 和 $y$ 的集合 | 把两个组合并 |
| `FIND-SET(x)` | 返回 $x$ 所在集合的代表 | 问 $x$ 属于哪个组 |

### 应用：连通分量

```
CONNECTED-COMPONENTS(G):
    for each vertex v ∈ G.V:
        MAKE-SET(v)
    for each edge (u, v) ∈ G.E:
        if FIND-SET(u) ≠ FIND-SET(v):
            UNION(u, v)

SAME-COMPONENT(u, v):
    return FIND-SET(u) == FIND-SET(v)
```

> **大白话**：图的连通分量问题 — 一开始每个人自成一组，每处理一条边就把两端的人合并到一组。最后问两个人是否连通，就看他们是否同组。

## 2. 链表表示 (Linked-list Representation)

### 结构

每个集合用一个**链表**表示：
- 每个节点存：集合成员、指向下一个节点的指针、指向集合对象的指针
- 集合对象有 `head`（头）和 `tail`（尾）指针
- **代表元素** = 链表的第一个元素

### 简单实现

| 操作 | 时间 | 说明 |
|------|------|------|
| `MAKE-SET(x)` | $O(1)$ | 创建单节点链表 |
| `FIND-SET(x)` | $O(1)$ | 沿指针找到集合对象，返回 head |
| `UNION(x, y)` | $O(n)$ | 把短链表接到长链表后面，更新所有指针 |

### 问题

最坏情况：$n$ 次 `MAKE-SET` + $n-1$ 次 `UNION` 可以达到 $O(n^2)$ 时间。

### 加权合并启发式 (Weighted-union Heuristic)

**总是把短链表接到长链表后面**。

**定理 19.1**：用加权合并，$m$ 次操作（$n$ 次 `MAKE-SET`）的时间为 $O(m + n \log n)$。

> **大白话**：每次都把小组合并到大组里，这样每个人最多被更新 $\log n$ 次指针。

## 3. 不相交集合森林 (Disjoint-set Forests)

### 结构

用**有根树**表示每个集合：
- 每个节点只指向父节点（`x.p`）
- **根节点**就是代表元素（`x.p = x`）
- 每个节点有 `x.rank`（秩，高度上界）

### 基本操作

```
MAKE-SET(x):
    x.p = x
    x.rank = 0

FIND-SET(x):
    if x ≠ x.p:
        x.p = FIND-SET(x.p)  // 路径压缩！
    return x.p

UNION(x, y):
    LINK(FIND-SET(x), FIND-SET(y))

LINK(x, y):
    if x.rank > y.rank:
        y.p = x
    else:
        x.p = y
        if x.rank == y.rank:
            y.rank = y.rank + 1
```

---

## 4. 按秩合并 (Union by Rank)

### 思想

- 每个节点维护一个 `rank`（秩），是该节点高度的**上界**
- `MAKE-SET` 时 rank = 0
- `UNION` 时，**让 rank 小的根指向 rank 大的根**
- 如果 rank 相等，任选一个作为父节点，其 rank + 1

### 为什么有效？

rank 小的树挂到 rank 大的树下面，不会增加大树的高度。这样树的高度增长很慢。

> **大白话**：矮树挂到高树下面，总高度不增加。就像小公司合并到大公司里，组织架构不变。

### 单独使用的效果

只用按秩合并（不用路径压缩）：$m$ 次操作的时间为 $O(m \log n)$。

---

## 5. 路径压缩 (Path Compression)

### 思想

在 `FIND-SET` 的过程中，把**查找路径上的所有节点直接指向根**。

```
FIND-SET(x):
    if x ≠ x.p:
        x.p = FIND-SET(x.p)  // 递归找到根，顺便把沿途节点都指向根
    return x.p
```

### 效果

- 第一次 `FIND-SET` 可能要走很长的路径
- 之后路径上的所有节点都直接指向根
- 后续的 `FIND-SET` 几乎 $O(1)$

> **大白话**：找组长的时候，顺便把路上遇到的人都直接挂到组长下面，下次找就快了。

### 两遍方法

`FIND-SET` 是两遍的：
1. 第一遍（递归上去）：找到根
2. 第二遍（递归回来）：把路径上每个节点的父指针改为根

### 路径压缩不改变 rank

路径压缩让树变扁平，但**不更新 rank**。rank 只是高度的上界，不再是精确高度。

---

## 6. 两种启发式联合使用

### 时间复杂度

**定理**：按秩合并 + 路径压缩，$m$ 次操作（$n$ 次 `MAKE-SET`）的时间为 $O(m \cdot \alpha(n))$

其中 $\alpha(n)$ 是 **Ackermann 函数的反函数**，增长极其缓慢。

### $\alpha(n)$ 有多小？

| $n$ 的范围 | $\alpha(n)$ |
|-----------|-------------|
| $[0, 2^{65536}]$ | $\le 4$ |
| 宇宙中原子数 | $\le 4$ |

> **大白话**：对于任何实际可能出现的数据规模，$\alpha(n) \le 4$。所以实际上每次操作就是 $O(1)$！这是**近乎线性**的。

### 各种方案对比

| 方案 | m 次操作时间 |
|------|-------------|
| 链表 + 简单合并 | $O(m + n^2)$ |
| 链表 + 加权合并 | $O(m + n \log n)$ |
| 森林 + 按秩合并 | $O(m \log n)$ |
| 森林 + 路径压缩 | $O(m \log n)$（最坏） |
| 森林 + 按秩合并 + 路径压缩 | $O(m \cdot \alpha(n))$ ≈ $O(m)$ |

## 7. Ackermann 函数与反函数

### Ackermann 函数

$$A_k(j) = \begin{cases} j + 1 & \text{if } k = 0 \\ A_{k-1}^{(j+1)}(j) & \text{if } k \ge 1 \end{cases}$$

其中 $A_{k-1}^{(i)}$ 表示函数迭代 $i$ 次。

- $A_0(j) = j + 1$
- $A_1(j) = 2j + 3$（大约）
- $A_2(j) = 2^{j+3}(j+3) - 3$（大约是指数级）
- $A_3(j)$ 已经是**超指数**级别的了
- $A_4(j)$ 大到无法想象

### 反函数 $\alpha(n)$

$\alpha(n) = \min\{k : A_k(1) \ge n\}$

因为 $A_k$ 增长极快，$\alpha(n)$ 增长极慢。
